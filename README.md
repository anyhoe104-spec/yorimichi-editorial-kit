# yorimichi-editorial-kit

note連載「AIと寄り道編集部」を運用するために使っている編集資料です。

5人の架空部員がそれぞれ別の個人開発プロジェクトを担当し、その開発過程を記事にしています。このリポジトリには、その記事をAIに書かせるときに使っている文体仕様とテンプレートを置いています。

- note：https://note.com/aiyorimichi

## これは何のための資料か

AIに記事を書かせると、二つの問題が起きます。

ひとつは、実装していないものを実装済みとして書いてしまうこと。もうひとつは、書き手を複数用意しても語りが混ざって区別がつかなくなること。

このリポジトリの資料は、その二つを止めるために作ったものです。前者は内部編集メモとプロットの事実境界で、後者は文体仕様で対処しています。

## 収録内容

```
docs/
  principles.md              事実と創作の境界、盛らないための規律
  voice-specs/
    README.md                5人の語り分けマトリクス
    momoi-kenji.md           桃井ケンジ（ゲーム開発）
    shiraishi-hina.md        白石ヒナ（ニュースアプリ）
    kurose-reina.md          黒瀬レイナ（サイドビジネス）
    kinjo-masaru.md          金城マサル（生活改善アプリ）
    shido-takumi.md          紫藤タクミ（資格学習）
templates/
  internal-memo.md           内部編集メモ（記入前）
  internal-memo.example.md   内部編集メモの記入例（公開済み記事をもとにした実例）
  episode-plot.md            連載プロットの雛形（記入前）
  image-guide.md             画像配置ガイド（記入前）
  social.md                  SNS投稿パーツ（記入前）
  publish-checklist.md       公開前チェックリスト
```

`docs/voice-specs/` の5点は実際に運用している完成版です。`templates/` は記入前の雛形なので、自分の題材に合わせて埋めて使えます。粒度の参考として、内部編集メモだけ記入済みの実例（`internal-memo.example.md`）を置いています。

## 使い方

1. 記事本文を生成する前に、該当部員の文体仕様と、そのプロジェクトのプロット・内部編集メモをAIに読ませる
2. 生成後、文体仕様の末尾にあるチェックリストで自己検証させる
3. 査読時は、禁止表現リストと語り分けマトリクスの両方を確認する

文体仕様は、曖昧な形容（「丁寧な語り口で」など）を避け、一人称の固定、箇所数の上限、禁止語と置き換え先のように、機械的に判定できる形で書いています。そうしないと生成がぶれます。

## 記事で扱っているプロジェクト

公開しているもの。

- CAKING！（ケーキ店経営ゲーム）：https://github.com/anyhoe104-spec/caking-game
- Personal-Newsroom（個人ニュースアプリ）：https://github.com/anyhoe104-spec/Personal-Newsroom

残り3つ（サイドビジネス構築、Life Score Advisor、資格学習記録）は、顧客向けの設計資料や個人の生活データを含むため非公開にしています。

## 注意

連載に登場する5人の部員は、AIによって生成された架空のキャラクターです。人格、語り、記事内の会話や心情は創作です。各プロジェクトの進捗や成果物については、実際のリポジトリ、作業ログ、設計資料をもとにしています。

この資料に登場する部員名・設定は、その創作の一部です。そのまま使うより、構造だけ借りて自分のキャラクターに置き換えることを想定しています。
