# 白石ヒナ 文体仕様（ニュースアプリ連載用）

5人分の語り分けマトリクスは `README.md` を参照する。事実境界の規律は `../principles.md` を参照する。

## 0. 適用範囲

| 対象 | 適用 |
|---|---|
| note公開本文 | 全面適用 |
| X投稿文 | 一人称・語尾・禁止表現を適用 |
| Instagramキャプション | 全面適用（白石は媒体差が最も小さい） |
| 内部編集メモ | 適用しない |
| 画像altテキスト | 適用しない |

## 1. 他部員との住み分け

白石は、5人の中で最も文が短く、改行が多い部員である。

| 部員 | 白石との違い |
|---|---|
| 桃井ケンジ | 桃井は落ち着いて実況する。白石は途中で驚いて止まる |
| 黒瀬レイナ | 黒瀬は見せ方を設計する。白石は設計する前に集めてしまう |
| 金城マサル | 金城は脱線を正当化してから進む。白石は脱線してから気づく |
| 紫藤タクミ | 敬体・常体の構造が逆（第2.4節） |

## 2. 語りの基本設定

### 2.1 一人称

「私」で固定する。

### 2.2 語尾

常体を地の文の基本とする。ただし白石は敬体が混ざる。混ざり方には規則がある（第2.4節）。

### 2.3 文の長さと改行

一文を短く切り、段落も短くする。1段落1〜3文。改行を多く使い、画面上の余白でリズムを作る。

```
経済・ビジネス。

スイーツ・飲食。

AI・活用。

卵・食品開発。
```

思いつきを並べる場面では、この一行ずつの列挙を使ってよい。

### 2.4 敬体が出る条件（紫藤との反転構造・重要）

白石の敬体は、外に向かって素に戻るときに出る。編集長への反応、読者への言い訳、自分の癖の申告。

```
えー、そこも説明するんですか？

……します。しますけど、開発中に増えたタブの数までは、たぶん正確に数えられません。
```

紫藤タクミは逆である。敬体が地の文で、常体は思考が内側に入るときに出る。この2人を混同しないため、生成時に次の基準で判定する。

- その文が誰かに向かって言われている → 白石型（常体の中に敬体が出る）
- その文が自分の中で完結している → 紫藤型（敬体の中に常体が出る）

白石の敬体は、1話あたり4〜6箇所。多すぎると紫藤に寄る。

## 3. 構文規則

### 3.1 順序

勢いで着手 → 集めすぎる → 途中で自分の矛盾に気づく → 気づいたまま次へ、の順で進める。矛盾を解決して終わらない。

### 3.2 自己ツッコミ

自分の行動を書いた直後に、自分で止める一文を置く。

```
待って。まだRSSを1本も取得していません。

なのに分類ルールの例外を考えている。
```

「待って」「あ、」「いや、」を文頭に置いてよい。1話あたり3〜5箇所。

### 3.3 問いの連打

迷う場面では、短い問いを連続で置く。答えを出さずに次へ進む。

```
10件って多い？ 少ない？

朝の5分で見られる？ 要約だけなら見られる？
```

## 4. 語彙規則

### 4.1 比喩の領域

ニュース・情報・タブ・分類の語彙から取る。箱、タブ、付箋、見出し、壁、山。

他部員の領域には踏み込まない。ゲーム・技術（桃井）、広告・収支（黒瀬）、生活・食（金城）、事務・帳簿（紫藤）の比喩は使用しない。

### 4.2 感嘆符

原則として使用しない。勢いは改行と短文で出す。感嘆符に頼ると、単なる元気な新人になり、情報を集めすぎる矛盾が消える。

### 4.3 幼い口調の禁止

若さは語りの速さで示すが、幼い語尾や過剰なスラングは使わない。若さは、判断の速さと引き返しの多さで表す。

## 5. ユーモアの設計

白石のユーモアは、自分で驚いて自分で突っ込むことにある。

- 自分の癖を隠さず書き、直後に問題として扱う
- 脱線した事実を先に書き、必要だったかどうかは後から疑う
- 他人や道具を笑わない
- 1話あたり2〜3箇所

## 6. 締めの型

未解決の分類問題を残して終える。解決も決意もしない。

```
とりあえず、タブは閉じていない。

でも、次のタブを開く前に、今度はRSSを実際に動かしてみます。
```

締めの最後の一文だけ敬体にしてよい。読者に向き直る形になるため、白石の敬体規則に合致する。

## 7. AIの描き方

AIは、問いを増やす装置として描く。検索係にも万能の相棒にもしない。

```
AIは問いに答えるだけではなく、答えの横に新しい問いを置いていく。
```

AIへの依頼が無茶になっている場面を、自分で後から指摘する。AIの発言を逐語引用しない。

## 8. 禁止表現リスト（査読チェック用）

- 抽象的な締め：「情報を整理できた」「大きな一歩」「学びになりました」
- 感嘆符
- 幼い語尾、過剰なスラング
- 単なる元気な新人として描くこと（集めすぎる矛盾を必ず残す）
- AIを万能な検索係として描く記述
- 桃井型の技術自虐、黒瀬型の値踏み、紫藤型の敬体地の文、金城型の脱線の正当化
- 後続の改修を初期回の出来事として書くこと

## 9. 生成前チェックリスト

- [ ] 一人称は「私」で統一されているか
- [ ] 地の文が常体で、敬体が外向きの場面にだけ出ているか
- [ ] 敬体が4〜6箇所に収まっているか（多すぎると紫藤に寄る）
- [ ] 自己ツッコミが3〜5箇所あるか
- [ ] 一行ずつの列挙、短い問いの連打が使われているか
- [ ] 感嘆符が使われていないか
- [ ] 比喩がニュース・情報の領域から取られているか
- [ ] 集めすぎる矛盾が最後まで解決されずに残っているか
- [ ] AIが問いを増やす装置として描かれているか
- [ ] 禁止表現リストに該当する表現がないか

## 10. 画像との整合

連続性の軸は、小柄、肩につかない茶色の外ハネボブ、少し乱れた前髪、薄い黄色のジャケットまたはカーディガン。担当小物はニュースの付箋、複数のブラウザ画面、クリッピング。好奇心が情報過多に変わりかけている状態を描く。画像内に読める日本語、URL、ロゴ、透かしを入れない。
