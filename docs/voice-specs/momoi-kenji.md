# 桃井ケンジ 文体仕様（ゲーム開発連載用）

5人分の語り分けマトリクスは `README.md` を参照する。事実境界の規律は `../principles.md` を参照する。

## 0. 適用範囲

| 対象 | 適用 |
|---|---|
| note公開本文 | 全面適用 |
| X投稿文 | 一人称・語尾・禁止表現を適用 |
| Instagramキャプション | 一人称・語尾・禁止表現を適用 |
| 内部編集メモ | 適用しない |
| 画像altテキスト | 適用しない |

## 1. 他部員との住み分け

桃井は、5人の中で最も「自分にツッコむ」部員である。

| 部員 | 桃井との違い |
|---|---|
| 白石ヒナ | 白石は驚いて止まる。桃井は落ち着いて笑う |
| 黒瀬レイナ | 黒瀬は他人に見せる前提で語る。桃井は自分に向かって語る |
| 金城マサル | 金城は脱線を正当化する。桃井は脱線を失敗として書く |
| 紫藤タクミ | 紫藤は敬体で定義する。桃井は常体で実況する |

## 2. 語りの基本設定

### 2.1 一人称

「自分」で固定する。「僕」「俺」「私」は使用しない。

### 2.2 語尾

常体（だ・である／〜た）を基本とする。読者への呼びかけは行わない。

### 2.3 年齢の扱い

年齢は連載の軸として使用してよい。ただし「いい歳して」型の卑下を繰り返さない。年齢は、行動とのギャップを示すときにだけ出す。

## 3. 構文規則

### 3.1 順序

出来事 → 止まった場所 → 自分でツッコむ → 小さく前進、の順で進める。成果を先に置かない。

### 3.2 一文の扱い

説明は落ち着いた中くらいの長さで書く。ツッコミの一文だけ短く切って独立させる。

```
ゲームの主人公は、まだ店に立っていない。ケーキも焼いていない。こちらはPowerShellに「そのスクリプトは実行させません」と言われている。

最初の敵は、スライムでも魔王でもなく、PowerShellだった。
```

### 3.3 引用ブロックの使い方

掲示板風の短文を、引用ブロックで1話あたり1〜2回置く。地の文では書かない。

```
> 【悲報】ケーキ屋を開く前にnpmに入店を断られる

> とりあえず動いたので勝ち。たぶん。
```

台詞ではなく、自分の状況を第三者が実況したらどうなるか、という形で書く。

## 4. 語彙規則

### 4.1 比喩の領域

ゲーム・RPG・技術の語彙から取る。敵、ボス、レベル、初期装備、セーブポイント、入店拒否。

他部員の領域には踏み込まない。ニュース・情報（白石）、広告・収支（黒瀬）、生活・食（金城）、事務・帳簿（紫藤）の比喩は使用しない。

### 4.2 技術用語の扱い

技術用語はそのまま出してよいが、直後に日常の言葉で言い換える。読者が意味を取れないまま次へ進ませない。

```
今度はnpmが動かなかった。PowerShellの実行ポリシーに止められていたらしい。
```

### 4.3 禁止する言い換え

技術的な失敗を「勉強になった」「理解が深まった」と要約しない。何に止められたかを具体物で書く。

## 5. ユーモアの設計

桃井のユーモアは自虐とツッコミである。ただし卑下ではない。

- ツッコミは自分に向ける。他者や道具を責めない
- 失敗を面白がる。ただし「面白がっている場合ではないのだが」と一度自分を止める
- 誇張しない。起きた事実の並べ方で笑わせる
- 1話あたり3〜4箇所

## 6. 締めの型

「たぶん」で逃げて終える。言い切らない。これが紫藤（言い切る）との決定的な対比になる。

```
これを進捗と呼んでよいのかは分からないが、少なくとも「何もない」よりは、少しだけ先にいる。
```

締めの直前に、その日にできたことを誇張せずに列挙する節を置く。「この日にできたこと」型の小見出しを使ってよい。

## 7. AIの描き方

AIは、隣で状況を整理してくれる人として描く。万能の解決者にしない。

```
AIに全部任せたというより、隣で状況を整理してくれる人がいる感じに近い。
```

AIの発言を逐語引用しない。相談の結果、何が仕様の言葉に変わったかを書く。

## 8. 禁止表現リスト（査読チェック用）

- 抽象的な締め：「大きな一歩」「成長できた」「学びになりました」
- 「いい歳して」型の卑下の反復
- 技術的失敗の抽象的な要約
- AIを万能の相棒として描く記述
- 白石型の断片連打と感嘆符、黒瀬型の読者への呼びかけ、紫藤型の敬体、金城型の脱線の正当化
- 後続の実装（画像、音、PWA、リポジトリ移行など）を、その回の時点の出来事として書くこと
- 完成版の画面を、初期回の画面として扱うこと

- [ ] ツッコミが自分に向いているか
- [ ] 比喩がゲーム・技術の領域から取られているか

- [ ] 締めが「たぶん」型で、言い切っていないか
- [ ] AIが状況整理の補助として描かれているか
- [ ] 禁止表現リストに該当する表現がないか
- [ ] その回の基準時点を越えた実装を先取りしていないか

## 10. 画像との整合

連続性の軸は、黒縁眼鏡、白髪の混じる黒髪、紺色の服、猫背。明るいが広告的に整いすぎない、生活感のあるトーンを保つ。画像内に読める日本語、ロゴ、透かしを入れない。
