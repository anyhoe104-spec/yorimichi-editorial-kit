# 部員文体仕様 共通README（5人の語り分けマトリクス）

最終更新：2026-09-14

## この資料の目的

AIと寄り道編集部の5人の架空部員について、記事本文の生成・改稿・査読時に参照する文体規定を保管する。各話の事実境界（実装済みと検討中を混ぜない、実機確認を完了扱いしない、価格・収益を実績として書かない）は各プロジェクトのプロット・内部編集メモ側で定義し、本フォルダはその上に重ねる文体の制約のみを扱う。

複数部員の記事を並行制作するため、語りが混ざる事故を防ぐことが最大の目的である。

## 敬体・常体の反転構造（重要）

白石ヒナと紫藤タクミは、どちらも敬体と常体を混ぜるが、構造が逆である。混同すると2人の区別が消えるため、生成時は必ず確認する。

- **白石ヒナ**：常体が地の文。敬体は、編集長や読者に向かって素に戻るとき（言い訳、驚き、弁解）に出る。外向き。
- **紫藤タクミ**：敬体が地の文。常体は、思考が内側に入るとき（気づいた内容そのもの）に出る。内向き。

判定基準：その文が誰かに向かって言われているなら白石型、自分の中で完結しているなら紫藤型。

## 全員共通の禁止事項

- 抽象的な締め：「大きな一歩」「成長できた」「学びになりました」
- AIを万能の相棒として描く記述
- 実装していないものを実装済みとして書くこと
- 価格・収益・顧客数を実績として書くこと（企画上の仮説と明記する）
- 教材・記事・楽曲などの逐語引用
- 他部員の語りの型を借用すること

## 運用

1. 記事本文の生成前に、該当部員の文体仕様と、そのプロジェクトのプロット・内部編集メモを読む
2. 生成後、各文体仕様の末尾にあるチェックリストで自己検証する
3. 査読時は、禁止表現リストと語り分けマトリクスの両方を確認する
